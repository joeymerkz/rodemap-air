## Welcome screen — how it hooks the session lifecycle

No new state, callbacks, or lifecycle code. `OverviewContent` (MainScreen.kt) already collects
`viewModel.serverState`, `viewModel.connectionCount`, and `viewModel.mirroringActive` — StateFlows
fed by `MainViewModel.updateFromService()`, which MainActivity polls from `AirPlayService` every
200 ms. The welcome renders under the **pre-existing** idle condition in the same content `Box`
that hosts the video surface:

```kotlin
if (state == ServerState.RUNNING && (mirroringActive || idlePreview)) {
    video()
}
if (state != ServerState.RUNNING || connections == 0) {
    IdleWelcome( … )
}
```

When a session starts, the flows flip: the welcome leaves composition and the video surface (or
Now Playing) takes the Box — including the existing auto-fullscreen path. When the session ends
(connections back to 0, or the receiver stops), the same condition is true again and the welcome
returns. The status line reuses the pre-existing selection expression verbatim
(permission-needed → `local_network_desc`; STOPPED/RUNNING/ERROR → the status strings), and the
instruction line shows only while the receiver is running and shows the **live** receiver name —
the `Prefs.SERVER_NAME` value already collected in `OverviewContent`:

```kotlin
Text(text = stringResource(R.string.idle_instruction, serverName), …)
// "On your iPhone or iPad, open Control Center, tap Screen Mirroring, and pick “%1$s”."
```

Welcome content, top to bottom: Rodemap logo (`@drawable/ic_launcher_foreground_img`, the v1.0.0
brand art), "Rodemap Air" wordmark, the tagline "Less busywork. More progress." in the accent
color, the status line, and the one instruction above. The controls card below (receiver name,
connection count, Start/Stop) is unchanged.

## Strings: rewrote vs kept

**Rewrote in Rodemap's voice** (fresh lines, plain words, TV-first):
- Notifications: `notification_title` ("Rodemap Air is on"), `notification_text` ("Ready when you are"), `notification_pin_title`.
- Tabs/sections: `tab_overview` (Overview → **Home**), `section_server` (Server → **Receiver**), `section_decode` (Decode → **Playback**), `section_developer` (Developer → **Under the hood**, matching Rodemap's product language).
- Home/status: `server_stopped`, `waiting_for_connection`, `waiting_for_playback`, `error_starting_server`, `stopped_label`, `btn_open_settings`, `local_network_label`, `local_network_desc`, `unknown_track`.
- Settings labels + descriptions: receiver name/port, auto-start, boot start, background run, PIN (the "(Beta)" tag is gone), new-device takeover, discovery, launch-on-connect, welcome-screen preview, fullscreen-on-connect, keep-screen-on, offer video/mirroring/audio, ALAC/AAC announcements, resolution/FPS/overscan descriptions.
- Diagnostics ("Under the hood"): the three toggles whose labels were literally raw Android keys are now plain English with the key kept in the description for traceability — `setting_enforce_sdr` ("Keep the picture in SDR"), `setting_key_allow_frame_drop` ("Let the decoder drop frames"), `setting_realtime_decoder_priority` ("Real-time decoder priority"), `setting_operating_rate` ("Max decoder rate") — plus plain-voice passes on software decoding, volume sync, low-latency audio, frame pacing, custom audio delay, both audio buffers, stream-stats overlay and logging. Every existing capability stays reachable in the same place; nothing was removed or re-gated.

**Kept factual** (verbatim or near-verbatim, per brief): `app_name`, all format-bearing strings
(every `%` specifier machine-checked unchanged), codec/format names (`setting_h265` title,
resolution/FPS placeholders, chip labels Auto/On/Off/Custom/Portrait/Landscape), all
content descriptions, volume/download/player-control/scale labels, Logs screen strings, and the
entire `debug_*` overlay set (stream stats are data, not copy).

## Flagged, not forced

- **Typography**: no bundled font was added — the repo ships no font assets and adding one
  means a new binary + license review. The welcome screen gets its premium feel from the
  logo, hierarchy, weight, and color on the default typeface. If a Rodemap font is chosen
  later, it drops into `AirPlayTheme` as a `Typography` in one place.
- **Dark-only**: intentional. `AirPlayTheme`'s `darkTheme` parameter is retained so existing
  call sites compile unchanged, but the scheme no longer follows the system theme.
