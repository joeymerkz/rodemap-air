# Rodemap Air v1.2 — "Link to Rodemap" Pairing Client Manifest

Base: the v1.1.0 tree (see `V1.1_MANIFEST.md`). Version: versionCode 3, versionName "1.2.0".
Goal: the TV receiver links to the owner's Rodemap account so it appears in his Rodemap Air
module. The app POSTs to `https://rodemap.app/api/air/receiver/enroll` (6-digit code →
`{ receiverId, token }`) and, while linked, sends a heartbeat every 60 s to
`/api/air/receiver/heartbeat` with `Authorization: Bearer <token>`. Engine untouched: nothing
under `app/src/main/cpp/`, no submodule changes, Kotlin package/namespace unchanged,
`NativeBridge` untouched, signing untouched, **no new permissions, no new dependencies**
(HTTP is `HttpURLConnection` + `org.json`, both already used by the app — DacpController /
SettingsReceiver).

## How the pieces fit the contract

- **Enroll** — `POST /api/air/receiver/enroll`, JSON `{ code, model, appVersion, ipLan,
  receiverName }`. `model` = `Build.MODEL`; `receiverName` = the live `SERVER_NAME` pref
  (falls back to its default when blank, same rule the service uses at server start). On 200
  the returned `token` and `receiverId` are written to the prefs above; any other status
  surfaces the body's `{ error }` in the dialog.
- **Heartbeat** — `POST /api/air/receiver/heartbeat`, header `Authorization: Bearer <token>`,
  JSON `{ ipLan, appVersion, receiverName }`, every 60 s while the app process is alive.
  Scheduled inside the existing AirPlay foreground service (`LifecycleService.lifecycleScope`,
  started in `onCreate`) — no second service, no WorkManager, no new permissions. The loop
  checks the stored token each round, so linking/unlinking takes effect without a restart.
  On **401** the token + receiverId are cleared in `RodemapLink.heartbeat()`; the Settings UI
  observes the token pref through the existing `viewModel.pref(...)` flow, so it returns to
  the not-linked ("Link again") state on its own. Network errors keep the link and retry next
  round.
- **Token storage** — the app's existing private SharedPreferences file ("settings", MODE_PRIVATE),
  via the same `Pref` machinery as `SERVER_NAME`. Note: the token is therefore visible to the
  app's pre-existing `SettingsReceiver` settings dump (gated by `android.permission.DUMP`,
  same as every other setting) — no new exposure surface was added.
- **appVersion** — the contract calls it "BuildConfig versionName", but this module does not
  generate `BuildConfig` (the `buildConfig` build feature is off and nothing references it).
  `RodemapLink.appVersion()` reads the identical value from `PackageManager`
  (`getPackageInfo(...).versionName`), so no build-file change beyond the version bump was
  needed.
